## Project Context

A BepInEx 6 (BepInEx.Unity.IL2CPP) / Harmony mod for Moon Sweepers (DragDropGames, Steam app 5335510, Unity 6000.6, IL2CPP since 2026-10-24; the Mono build and BepInEx 5 are gone, 0.2.0 was the last Mono release; Steamworks.NET, Input System) that adds a host admin menu on F1 for kicking and banning crewmates. The game's code lives in the `MoonCleaners` namespace (still `MoonCleaners.*` in the Il2CppInterop assemblies; System types are `Il2CppSystem.*`, game private fields are public properties). Packaged for Thunderstore under `darkharasho`.

## How the kick works

There's no kick in the game, and its multiplayer is a Steam lobby plus a full mesh of `SteamNetworkingMessages` sessions: every member sends to every member in `MoonSteamLobby.Members` and accepts sessions from anyone `MoonSteamLobby.IsMember` approves (see `MoonCrewSession`: `Receive`, `SendToCrew`, `DropMissing`, the session-request callback). Steam won't let the owner remove a lobby member, so:

- `Patches/LobbyPatches.cs` postfixes `MoonSteamLobby.RefreshMembers` (removes blocked players from the static `members` list, an `Il2CppSystem.Collections.Generic.List`) and `MoonSteamLobby.IsMember` (returns false for them). On the host that drops their packets, stops sends to them, destroys their avatar and closes their session. A client that joins a shift needs `WorldRequest` answered; when it's ignored the game's own 45s join timeout makes them leave the lobby.
- The host publishes the list as lobby data `darkharasho.kicked` (comma-separated SteamID64s). Modded crewmates read it in the same postfix and filter the same way; a listed player leaves (`MoonSession.ReturnToMenu`).
- A vanilla kicked player already in a shift stays in the Steam lobby with a frozen copy of the Moon until they leave; vanilla crewmates still see them. This is the known limit.

## UI and input

IMGUI (`AdminMenuController.OnGUI`, styles in `Theme.cs`). **Only `GUI.Label` and `GUI.DrawTexture` work**: every IMGUI control that takes a control id (GUI.Box/Button/TextField/sliders/BeginGroup, all of GUILayout, GUI.Window) throws "Method unstripping failed" in this build. So `Ui.cs` draws everything with Label (a style with a background texture is a box; hover is a second style) into explicit rects from the small `Pane`/`Line` cursor, and the mod does its own input in `MenuInput`: mouse from the Input System (`Mouse.current`, flipped and unscaled into GUI space; a press is used once, whoever takes it clears `Click`), typed characters from IMGUI KeyDown events into one focused text field, sliders dragged by position, mouse-wheel scrolling with manual row culling and cover bars over half-visible rows. Only the Repaint pass draws/acts; Layout only snapshots lists. Text sizes are estimated (`Theme.TextWidth/TextHeight`). Styles/textures are created lazily in `OnGUI`. The game has no UI Toolkit documents to borrow a theme from. While open: `MoonInput.Typing = true` (PlayKeyboard/PlayMouse go null, so no play input and no pause on Esc; it stays "typing" for the frame it's cleared), `MoonWalker.UIBlocked = true` in a shift, free cursor, `EventSystem.current` disabled. IMGUI lists are snapshotted on the Layout event so a kick mid-frame can't break the control ids.

## Layout

- `src/AdminMenu/Plugin.cs`: a `BasePlugin`; config (ToggleKey as text parsed by `Shortcut.cs`, CloseOnEscape, Bans), Harmony, `AddComponent<AdminMenuController>()` (which also registers it with IL2CPP, so it's a public class with an `IntPtr` ctor)
- `src/AdminMenu/AdminMenuController.cs`: hotkey, open/close, input lock, drawing
- `src/AdminMenu/Kicks.cs`: every call into the game for kicking; `Patches/LobbyPatches.cs`
- `src/AdminMenu/GameMoney.cs`: raw `il2cpp_runtime_invoke` wrappers for every game method taking or returning a `Decimal`
- `src/AdminMenu/HostTools.cs`: every call into the game for the Money, Give and World tabs and Knock down; drawn by `AdminMenuController.HostTools.cs`
- `src/AdminMenu/KickList.cs`, `MenuGate.cs`, `MoneyInput.cs`: pure logic, tested by `tests/AdminMenu.Tests`
- `scripts/package.sh` builds the Thunderstore zip (needs the interop and BepInEx 6 DLLs, see Notes). `scripts/update-refs.sh` and `lib/refs` are the old BepInEx 5/Mono reference assemblies and no longer match the csproj, so CI (`release.yml`) can't build until it's reworked
- Release: bump the version in `Plugin.cs`, the csproj, `thunderstore/manifest.json` and `CHANGELOG.md`, then push tag `v<version>` (Thunderstore and GitHub), or `v<version>-<suffix>` for a GitHub-only prerelease

## Notes

- Build references: `AdminMenu.csproj` (net6.0) uses the BepInEx 6 core DLLs (`BepInExCorePath`, default `~/.cache/ms-il2cpp/patched/BepInEx/core`) and the generated interop assemblies (`InteropPath`, default `~/.cache/ms-il2cpp/interop3`; BepInEx writes the same set to `<profile>/BepInEx/interop` on first launch). Override either with `-p:` or `Local.props`.
- Reading game code: there are no method bodies in the interop DLLs, only signatures. List them with `DOTNET_ROOT=/home/linuxbrew/.linuxbrew/opt/dotnet/libexec nice -n 19 taskset -c 0-3 ~/.dotnet/tools/ilspycmd -p -o /tmp/ms-interop-src ~/.cache/ms-il2cpp/interop3/Assembly-CSharp.dll` and confirm every member name/signature there. For logic, the old Mono decompile in `~/.cache/moonsweepers-decomp` is stale (pre-update). Run builds and tests the same low-priority way (`nice -n 19 taskset -c 0-3 dotnet build -m:2`); this machine freezes under full CPU load.
- IL2CPP gotchas: no reflection on game fields (use the interop properties); Il2Cpp lists have `get_Item(i)`/`Count`, not `[]`/`RemoveAll`; don't pass managed lambdas to Il2Cpp delegate types; `Il2CppSystem.Decimal` is broken in the interop (8 bytes, fields all at offset 0), hence `GameMoney.cs`; `MoonUpgradeTree.Node.requires` is an array of inline value tuples the wrapper can't index, so `HostTools.Requirements` reads it raw. The game now has its own `MoonSteamLobby.Kick/Ban/Unban/IsRemoved/PutOut` (`kicked`/`banned`, lobby data read by `ReadRemovals`); the mod still uses its own kick mechanism above and doesn't call them yet.
- BepInEx and the mod are managed by HML (`~/Documents/GitHub/hml`): Moon Sweepers is a custom Steam game there (`steam-5335510`, BepInEx 6 IL2CPP), test profile `il2cpp-test` (the csproj's default `ProfilePath`; the old Mono profile is `default`). Start it with HML's **Start modded**, which also sets up the Proton prefix; nothing goes in the game folder. `dotnet build -p:Deploy=true` (only then) copies the DLL into that profile's `BepInEx/plugins/darkharasho-moonsweepers-admin-menu`; never while the game runs (it maps the DLL). Otherwise install `dist/` zips through HML.
- Thunderstore had no Moon Sweepers community at first release. The workflow's `--community moon-sweepers` is a placeholder with `continue-on-error`; set the real slug once it exists and remove `continue-on-error`.
- Host tools: the host's `MoonWorld` is authoritative for the shared wallet (`CrewBuildMoney`, synced by `Kind.Wallet`) and per-player tools and upgrades (ids `"local"` / `"steam-<id64>"`, synced by the upgrade truth digest), so nothing needs crewmates modded. Grants add the price, then call the game's `TryPurchase*`, so purchase rules and saving apply; `MoonAchievements.NotEarned` keeps mod money out of Steam stats. The game's dev menu is behind `MoonDevTools.Enabled` (false in release, and true spawns a vehicle test yard), so we call what's underneath instead of patching it. A remote player's position and carried dust are theirs (`Kind.PlayerState`), so teleporting or giving dust to others would need them modded; `RunOver` is the only host-to-player body message.
- Protocol byte is 38 (`MoonCrewSession.Protocol`); the lobby version check means everyone runs the same game build.
